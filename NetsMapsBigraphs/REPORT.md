## 2. Модуль 1: Максимальный поток в транспортной сети (`net.c`)

### 2.1 Теоретические основы транспортных сетей
Транспортная сеть задается ориентированным графом $G = (V, E)$, где каждому ребру $(u, v) \in E$ сопоставлена неотрицательная **пропускная способность** $c(u, v) \ge 0$. Если ребро отсутствует, $c(u, v) = 0$.

Поток $f: V \times V \to \mathbb{R}$ в сети должен удовлетворять трём фундаментальным условиям:
1. **Ограничение по пропускной способности**: для любых $u, v \in V$:
   $$0 \le f(u, v) \le c(u, v)$$
2. **Антисимметрия**:
   $$f(u, v) = -f(v, u)$$
3. **Сохранение потока** (закон Кирхгофа): для любой промежуточной вершины $u \in V \setminus \{s, t\}$:
   $$\sum_{v \in V} f(u, v) = 0$$
   То есть суммарный входящий поток в вершину строго равен суммарному исходящему потоку.

Величина потока $|f|$ определяется как чистый поток, выходящий из источника $s$ (или входящий в сток $t$):
$$|f| = \sum_{v \in V} f(s, v)$$

### 2.2 Автоматическое определение источника и стока
В функции `find_source_and_sink` проводится структурный анализ сети без необходимости передачи номеров $s$ и $t$ через параметры CLI:
- Для каждой вершины вычисляются полустепени исхода ($\text{out\_degree}$) и захода ($\text{in\_degree}$).
- **Источник ($s$)**: вершина, в которую не входит ни одно ребро ($\text{in\_degree} = 0$), но из которой есть исходящие рёбра ($\text{out\_degree} > 0$).
- **Сток ($t$)**: вершина, из которой нет исходящих рёбер ($\text{out\_degree} = 0$), но в которую входят входящие рёбра ($\text{in\_degree} > 0$).
- Реализована строгая проверка корректности графа: если число источников или стоков не равно единице, выполнение прерывается с информативным сообщением об ошибке.

### 2.3 Принцип работы алгоритма Эдмондса-Карпа
Классический метод Форда-Фалкерсона оставляет выбор увеличивающего пути произвольным (например, с помощью DFS). В худшем случае на графах с большими пропускными способностями или иррациональными весами такой подход приводит к экспоненциальному числу итераций или отсутствию сходимости.

**Алгоритм Эдмондса-Карпа** решает эту проблему за счёт использования **поиска в ширину (BFS)** для нахождения *кратчайшего* по количеству рёбер увеличивающего пути в остаточной сети.
- **Временная сложность**: $O(V \cdot E^2)$, так как длина кратчайшего пути от $s$ к любой вершине монотонно не убывает в процессе работы алгоритма, а каждое ребро может стать «критическим» не более $O(V)$ раз.

#### Механизм остаточной сети (Residual Graph)
Для представления остаточной сети используется структура [`graph_t`](file:///D:/cpp%20programms/GraphsLab/NetsMapsBigraphs/include/graph.h#L12):
- Для каждого прямого ребра $(u, v)$ с исходной пропускной способностью $c(u, v)$ в остаточный граф добавляются два ребра:
  1. Прямое ребро $u \to v$ с остаточной пропускной способностью $c_f(u, v) = c(u, v) - f(u, v)$ (изначально $c(u, v)$).
  2. Обратное ребро $v \to u$ с остаточной пропускной способностью $c_f(v, u) = f(u, v)$ (изначально $0$). Обратные рёбра позволяют «откатывать» ранее направленный поток, если на последующих шагах обнаружен более выгодный маршрут.

#### Шаги итерации:
1. **Поиск пути (`bfs_augmenting_path`)**:
   Очередь FIFO обходит остаточный граф из $s$. В обход допускаются только рёбра, у которых остаточная пропускная способность строго больше нуля:
   ```c
   if (residual_cap > 0 && parent[v] == -1) {
       parent[v] = u;
       queue[q_tail++] = v;
   }
   ```
2. **Определение бутылочного горлышка (Bottleneck)**:
   При достижении стока $t$ восстанавливается путь по массиву предков `parent` и находится минимальная остаточная пропускная способность:
   $$\Delta = \min_{(u, v) \in \text{path}} c_f(u, v)$$
3. **Модификация остаточных пропускных способностей**:
   Вдоль найденного пути обновляются веса рёбер в `residual`:
   ```c
   edge_t *fwd_edge = find_edge(u_set, v);
   fwd_edge->weight -= bottleneck;

   edge_t *bwd_edge = find_edge(v_set, u);
   bwd_edge->weight += bottleneck;
   ```
4. **Суммирование**:
   К общей величине потока прибавляется $\Delta$:
   $$\text{max\_flow} \mathrel{+}= \Delta$$
   Итерации повторяются до тех пор, пока сток $t$ достижим из $s$ в остаточной сети.

5. **Вычисление фактического потока на рёбрах**:
   После завершения главного цикла для каждого исходного ребра сети поток восстанавливается как разность между исходной и оставшейся пропускной способностью:
   $$f(u, v) = c_{\text{orig}}(u, v) - c_{\text{residual}}(u, v)$$

## 3. Модуль 2: Поиск кратчайшего пути на карте высот (`map.c`)

### 3.1 Модель карты высот и метрика переходов
Входные данные представляют собой двумерную матрицу высот размером $R \times C$. Значение $h(r, c) = 0$ означает непроходимое препятствие (скала, пропасть), такие клетки полностью исключаются из графа.

#### Пространственная топология:
- Перемещения разрешены по 4 основным направлениям (ортогональная 4-связность): вверх, вниз, влево, вправо.
- Каждой проходимой клетке $(r, c)$ с $h(r, c) > 0$ сопоставляется плоский индекс вершины:
  $$u = r \times C + c$$
- Граф строится как неориентированный `graph_t *graph = allocate_graph(false)`.

#### Метрика веса ребра:
Для сохранения физического смысла перемещения по рельефу вес перехода между соседними клетками $u$ и $v$ складывается из базовой стоимости шага по плоскости и абсолютной разности высот:
$$\text{cost}(u, v) = 1 + |h(u) - h(v)|$$
Минимальный вес любого ребра равен $1$ (при движении по горизонтальной плоскости с равными высотами).

### 3.2 Принцип работы алгоритма A\* (A-Star)
Алгоритм A\* является обобщением алгоритма Дейкстры и относится к семейству эвристических методов поиска пути (Best-First Search).

Для каждой вершины $u$ вводятся три величины:
1. $g(u)$ — точная наименьшая стоимость пути от стартовой вершины до вершины $u$, найденная на текущий момент.
2. $h(u)$ — эвристическая оценка оставшейся стоимости пути от вершины $u$ до целевой точки $(r_{\text{goal}}, c_{\text{goal}})$.
3. $f(u) = g(u) + h(u)$ — полная ожидаемая стоимость пути от старта к цели через вершину $u$.

На каждом шаге алгоритм извлекает из множества ещё не обработанных вершин ту, у которой значение $f(u)$ минимально.

#### Допустимость (Admissibility) эвристик:
Эвристика $h(u)$ называется **допустимой**, если она никогда не переоценивает истинную оставшуюся стоимость достижения цели, то есть $h(u) \le h^*(u)$ для всех $u \in V$. При выполнении этого условия алгоритм A\* гарантированно находит математически оптимальный (кратчайший) путь.

В проекте реализованы две допустимые эвристики для варианта (b):
1. **Манхэттенская эвристика ($L_1$-метрика)**:
   $$h_{\text{Manhattan}}(r, c) = |r - r_{\text{goal}}| + |c - c_{\text{goal}}|$$
   Отражает минимальное количество шагов по ортогональной сетке до цели без учёта высот. Так как каждый шаг стоит минимум 1, $h_{\text{Manhattan}}$ строго не превосходит истинную стоимость пути.
2. **Евклидова эвристика ($L_2$-метрика)**:
   $$h_{\text{Euclidean}}(r, c) = \sqrt{(r - r_{\text{goal}})^2 + (c - c_{\text{goal}})^2}$$
   Отражает длину прямого отрезка на плоскости. В силу неравенства треугольника для ортогональной сетки всегда выполняется $h_{\text{Euclidean}} \le h_{\text{Manhattan}} \le h^*(u)$, что также гарантирует строгую допустимость.

### 3.3 Архитектурное решение в стиле Дейкстры
Для сохранения лаконичности и полного соответствия авторскому стилю реализации алгоритма Дейкстры, выбор вершины с минимальным $f(u)$ выполняется без тяжеловесных структур (таких как бинарные кучи или очереди с приоритетами), а посредством прямого сканирования рабочего массива:
```c
double min_f = INFINITY;
size_t min_index = size;

for (size_t i = 0; i < size; ++i) {
    if (!worked[i] && dist[i] != ULLONG_MAX) {
        const int r = names[i] / cols;
        const int c = names[i] % cols;
        const double h = calculate_heuristic(r, c, end.r, end.c, h_type);
        const double f = (double)dist[i] + h;

        if (f < min_f) {
            min_f = f;
            min_index = i;
        }
    }
}
```
После выбора вершины `min_index` производится обход её инцидентных рёбер через функцию [`find_set(graph->adj_list, names[min_index])`](file:///D:/cpp%20programms/GraphsLab/NetsMapsBigraphs/src/forward_list.c#L48). Для каждого соседа $j$ проверяется условие релаксации:
$$\text{new\_dist} = dist[\text{min\_index}] + weight$$
Если $\text{new\_dist} < dist[j]$, значение $dist[j]$ обновляется, а в массив `parent[j]` записывается индекс вершины `min_index`.

При достижении целевой точки поиск немедленно останавливается, фиксируется число просмотренных вершин для расчёта метрики покрытия:
$$\text{visited\_percentage} = \frac{\text{visited\_count}}{|V_{\text{graph}}|} \times 100\%$$
А также замеряется точное время работы алгоритма с помощью системного таймера `clock()`.

## 4. Модуль 3: Двудольные графы и максимальное паросочетание (`bipart.c`)

### 4.1 Теоретические основы двудольности
Граф $G = (V, E)$ называется **двудольным**, если множество его вершин можно разбить на два непересекающихся подмножества $L$ и $R$ ($V = L \cup R$, $L \cap R = \emptyset$) таким образом, что каждое ребро графа соединяет некоторую вершину из $L$ с некоторой вершиной из $R$:
$$\forall (u, v) \in E: \quad (u \in L \land v \in R) \lor (u \in R \land v \in L)$$
Внутри долей $L$ и $R$ нет ни одного ребра.

**Теорема Кёнига**: Граф является двудольным тогда и только тогда, когда он не содержит простых циклов нечётной длины.

### 4.2 Алгоритм проверки двудольности (2-Coloring BFS)
Проверка двудольности реализована через раскраску вершин графа в два цвета ($1$ и $2$) с помощью обхода в ширину.

#### Принцип работы:
1. Массив `colors[u]` инициализируется нулями ($0$ — вершина ещё не посещена).
2. Так как граф может состоять из нескольких несвязных компонент, алгоритм перебирает все вершины $0 \le start < n$. Если вершина ещё не раскрашена, она назначается стартовой для новой компоненты и красится в цвет $1$.
3. Запускается BFS: из очереди извлекается вершина $u$. Для каждого смежного ребра $(u, v)$:
   - Если вершина $v$ ещё не посещена ($colors[v] == 0$), ей присваивается противоположный цвет:
     $$colors[v] = (colors[u] == 1) ? 2 : 1$$
     и она помещается в очередь.
   - Если вершина $v$ уже посещена и имеет тот же цвет ($colors[v] == colors[u]$), это означает обнаружение цикла нечётной длины. Алгоритм немедленно останавливает работу и возвращает `false`.
4. Если все компоненты связности успешно раскрашены без противоречий, граф является двудольным.

### 4.3 Поиск максимального паросочетания (Алгоритм Куна)
**Паросочетанием** $M \subseteq E$ называется набор попарно несмежных рёбер графа (ни одна вершина не инцидентна более чем одному ребру из $M$). Паросочетание называется **максимальным**, если оно содержит наибольшее возможное количество рёбер среди всех допустимых паросочетаний графа.

#### Концепция дополняющих цепей (Augmenting Paths):
- Вершина называется **насыщенной** (matched), если она инцидентна некоторому ребру из текущего паросочетания $M$, и **ненасыщенной** (free), если такого ребра нет.
- **Чередующаяся цепь** — это простой путь, в котором рёбра поочерёдно принадлежат паросочетанию $M$ и не принадлежат ему.
- **Дополняющая цепь** — это чередующаяся цепь, оба конца которой являются ненасыщенными вершинами.

**Теорема Бержа**: Паросочетание $M$ является максимальным тогда и только тогда, когда в графе не существует ни одной дополняющей цепи относительно $M$.

Если дополняющая цепь найдена, то, инвертировав принадлежность её рёбер паросочетанию (рёбра вне $M$ включаются в $M$, а рёбра из $M$ исключаются), мы получаем новое корректное паросочетание с мощностью ровно на 1 больше:
$$|M'| = |M| + 1$$

#### Реализация алгоритма Куна:
В модуле `bipart.c` алгоритм Куна реализован через обход в глубину (DFS) с асимптотической сложностью $O(V \cdot E)$:
1. Массив `match[v]` хранит индекс вершины из доли $L$, с которой спарена вершина $v \in R$ (или $-1$, если вершина свободна).
2. Для каждой вершины $u \in L$ (то есть вершины с $colors[u] == 1$) вызывается процедура `try_kuhn(graph, u, visited, match)`:
   - Помечаем вершину $u$ как просмотренную на текущей итерации (`visited[u] = true`).
   - Перебираем всех соседей $v$ вершины $u$ напрямую через `find_set(graph->adj_list, u)`:
     - Если вершина $v \in R$ свободна (`match[v] == -1`), дополняющая цепь найдена: устанавливаем `match[v] = u` и возвращаем `true`.
     - Если вершина $v$ уже занята, рекурсивно пробуем перенаправить её текущего партнёра: `try_kuhn(graph, match[v], visited, match)`. Если партнёр смог найти себе другую свободную пару, освобождаем $v$ для $u$: `match[v] = u` и возвращаем `true`.
3. Мощность максимального паросочетания равна количеству успешных вызовов `try_kuhn`.
4. Для финального отчёта рёбра извлекаются из массива `match` и преобразуются в пары $(u + 1, v + 1)$ с 1-based нумерацией согласно требованиям задания.

## 5. Организация командной строки (CLI) в `main.c`

Точка входа программы осуществляет строгую валидацию входных параметров:
- **Выбор режима**: первым аргументом передаётся один из режимов: `net`, `map`, `bipart`.
- **Входной файл**: обязательный позиционный аргумент.
- **Выходной файл**: задаётся ключом `-o <output_file>`, по умолчанию используется значение `ans.txt`.
- **Координаты пути для карты**:
  - `-a <row> <col>` — стартовая точка;
  - `-b <row> <col>` — финишная точка.
  - Осуществляется строгая проверка корректности числового разбора через `strtol`.

### Безопасное управление ресурсами:
- При работе в режимах `net` и `bipart` граф считывается и парсится через `read_graph(fin)`. По завершении работы память гарантированно освобождается вызовом `free_graph(graph)`.
- В режиме `map` граф генерируется на основе карты высот и также корректно уничтожается в конце процедуры `run_map`.
- Утечки памяти и некорректные разыменования указателей полностью исключены.
